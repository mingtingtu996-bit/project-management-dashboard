## 0. 结论口径

本专项解决的是“外部资料和未来内部资料库如何变成可治理、可回放、可自动发布的工期资产”。它不是把 PDF、网页或企业手册直接写进现有 seed，也不是把外部节点工期当成真实历史样本。

允许达成的窄口径：

```text
外部 / 内部进度知识源可以直连、抽取、去重、形成候选进度资产；
候选资产经过校准回放、冲突检测、准度门禁、影响监控和回滚目标后，
低风险小半径校准结果可自动进入 canary / published runtime artifact；
高风险或强约束资产保留人工治理闸。
```

禁止达成或宣传的口径：

```text
公开手册中的工期节点已经自动覆盖系统工期 seed。
外部 PDF 抽取结果等同于企业内部历史项目沉淀。
候选外部资产可以直接改写 baseline、monthly plan、task_dependencies、actual 或关键路径事实。
```

## 2. 数据源连接样式

候选外部进度资产表必须按“连接器 + 文档 + 候选资产 + 校准结果 + 发布 readiness”组织，方便未来从公开资料切换到企业内部资料库。

| 层级 | 作用 | 典型来源 |
|---|---|---|
| `progress_knowledge_sources` | 记录数据源连接器、访问等级、可信等级、同步策略和治理边界 | 公开 PDF、广联达 / 品茗知识库、企业内网知识库、对象存储、数据库、API、Excel 台账 |
| `progress_knowledge_documents` | 记录单个文件 / 页面 / 表格的哈希、页码范围、版本、抽取质量 | 中建手册、地方工期定额、企业工期标准化手册、内部项目复盘文档 |
| `progress_asset_candidates` | 记录候选工期资产本体，不直接写 seed 或历史样本 | 工期定额、工序穿插、WBS 模板、工况修正系数、业态模型、资源假设 |
| `progress_asset_calibration_runs` | 记录一批候选资产如何和当前系统比对 | 覆盖率、偏差、冲突、准度回放、候选发布策略 |
| `progress_asset_calibration_results` | 记录逐资产校准结论和建议动作 | 无覆盖、已有覆盖、偏差过大、可自动 canary、需人工治理 |
| `progress_asset_publication_readiness` | 记录能否自动发布、发布到哪里、如何监控和回滚 | standardWorkDurationSeed、process constraint、WBS reference days、context factor、building pattern schedule model |

## 3. 候选资产类型

| asset_type | 示例 | 默认发布边界 |
|---|---|---|
| `duration_seed_candidate` | 标准层铝模 6 天 / 层、地下室 12 天 / 层、桩基 20 天 / 栋 | 只能先进入候选 seed 或 runtime canary，不直接改系统 seed |
| `process_interleaving_rule` | 砌体 8 层插入、精装在粗装 / 地面完成后插入 | 只能进入依赖 / 穿插候选，不能自动改已确认依赖 |
| `wbs_template_candidate` | 医院、会展、体育馆、学校、厂房、超高层专项进度模型 | 只能进入模板推荐与回放，不直接生成正式项目计划 |
| `context_correction_factor` | 地区工期定额、装配式、冬雨季、地下室层数、超高层高度修正 | 低风险小半径可自动 canary，高风险需人工治理 |
| `business_type_schedule_model` | 住宅、安置房、商业综合体、医院、机场、EPC 全周期模型 | 必须先跑 golden benchmark / replay，不可直接 production-ready |
| `resource_assumption` | 塔吊基础、爬架、铝模、流水段和工作面假设 | 只能作为施工组织候选和解释因子，不作为强排程约束 |

## 4. 自动发布门禁

本文件按 v1.4.22.4 和旧编号 v1.4.22.5 live 自升级门禁的自动化风格处理校准结果：默认不是“生成表后人工慢慢看”，而是“门禁能机器判定且影响半径可控时自动发布；门禁失败、高风险、强约束或越界写入时才进入人工”。校准结果必须能生成机器可读的 `publication_readiness + release_job_policy + observation_window + rollback_target`，让后续内部资料库接入后可以直接驱动发布作业。

| 门禁 | 通过后动作 | 失败后动作 |
|---|---|---|
| 来源可信 | `public / internal` 来源有文档哈希、页码 / 表格定位、抽取质量可读 | `candidate_only`，不进入发布包 |
| 适用范围 | 业态、地区、结构、层数、工法、阶段、单位明确 | `manual_governance_required` |
| 当前系统覆盖 | 能映射到现有 seed / rule / WBS / context factor 或明确是新增缺口 | `mapping_required` |
| 偏差阈值 | 与当前系统同类资产偏差在自动 canary 阈值内，或确认为缺口补齐 | 偏差过大进入人工治理 |
| 回放准度 | replay / shadow run 不造成 MAE、Bias、overcompensation 退化 | 阻断发布并保留校准证据 |
| 冲突清理 | 不与已发布公司 / 项目 override、事实锁定资产冲突 | 阻断或降级为候选 |
| 影响监控 | 有 canary 监控窗口、消费方、失败告警和 rollback target | 不允许发布 |

自动发布状态固定为：

```text
candidate_only -> auto_review_package -> auto_canary_ready -> auto_canary_active -> auto_published -> runtime_rolled_back
manual_governance_required / rejected 是旁路状态
```

低风险资产可以在门禁通过后自动进入 `auto_canary_ready` 或 `auto_canary_active`；高风险资产包括强依赖规则、关键路径规则、baseline / monthly plan 影响面、跨公司全局 seed 改写和大偏差替换，必须保持 `manual_governance_required`。

自动发布作业策略固定如下：

| readiness_status | human_review_policy | release_job_policy | 允许动作 |
|---|---|---|---|
| `auto_canary_ready` | `zero_human_review_when_gate_passes` | `enqueue_guarded_canary_release` | 自动排队调用专属 writer，生成可回滚 runtime artifact，并写观察窗 |
| `auto_canary_active` | `zero_human_review_when_gate_passes` | `monitor_canary_and_maybe_promote` | 自动监控 MAE / Bias / overcompensation / coverage，观察窗通过后可进入 `auto_published` |
| `auto_published` | `zero_human_review_when_gate_passes` | `monitor_published_and_keep_rollback_ready` | 继续监控并保留 rollback target |
| `manual_governance_required` | `batch_manual_approval_required` | `hold_for_governance_batch` | 只生成证据包和批量审批候选，不自动写 runtime |
| `candidate_only / blocked` | `not_publishable` | `retain_candidate_evidence_only` | 仅保留候选、抽取质量和缺口原因 |

因此，自动化发布不是等同于静默改正式 seed，而是把门禁通过的校准结果自动推入受控 canary / published 流水线；所有写入都必须带 `target_runtime_surface`、`target_writer_ref`、`consumer_refs`、`observation_window_days`、`rollback_target` 和 `readiness_evidence`。人工治理只处理无法机器判定或影响计划网络 / 事实承诺层的资产。

## 5. 校准结果如何修正现有数据

校准结果不直接修改现有 seed、任务、基线或历史样本。修正路径分四步：

1. **候选入库**：外部资料抽取得到 `progress_asset_candidates`，携带来源、哈希、页码、适用范围和候选值。
2. **校准回放**：`progress_asset_calibration_results` 对当前系统覆盖、偏差、冲突和 replay 结果出结论。
3. **受控发布**：门禁通过后写 `progress_asset_publication_readiness`，并由 `release_job_policy` 自动排队调用既有专属 writer 或发布链生成 canary / published runtime artifact；低风险通过项不再要求逐条人工确认。
4. **生产证据回流**：runtime 消费、accuracy、impact monitoring、rollback drill 和 scope provenance 进入 v1.4.22.6 的 production claim audit。

因此它修正的不是“现有数据行本身”，而是新增一版可回滚、可追溯、可灰度的 runtime / seed / rule / context artifact。旧版本保留，失败时 rollback。

## 10. 当前修正口径

已撤回“第二批候选资产预抽取”作为当前阶段产物。当前阶段只保留：

```text
source_catalog_expansion_before_candidate_extraction
```

也就是先把外部进度知识源做成可直连、可核验、可分级、可迁移到内部资料库的目录：

1. `official_direct_pdf / official_notice_attachment`：优先下载、哈希、抽表；
2. `enterprise_search_lead / local_pdf_origin_reverification`：先补官方来源、版本和哈希；
3. `third_party_index`：只能作为发现入口，不作为可信来源；
4. `product_official_page / product_case_page`：只做能力对标和 connector 样式参考，不产出 duration value；
5. `provincial_search_lead / infrastructure_search_lead`：作为后续检索 backlog，未核验前不进入校准。

因此 v1.4.22.5 当前可以声明“外部源目录已扩到大范围可接入清单”，但仍不能声明“外部资料已经足够校准系统所有工期资产”。下一步应先做来源核验、下载哈希、OCR / 表格抽取质量评估，再进入候选资产与自动发布 readiness。
