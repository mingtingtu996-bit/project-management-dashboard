## 0. 2026-06-01 final range-tree boundary (authoritative)

This v1.4-series plan follows the final range-tree model. There is no production history or existing user data that needs a compatibility layer.

Authoritative engineering object types are exactly: `phase / section / building / basement / floor / physical_zone / functional_area`.

The following compatibility surfaces are deleted and must not be reintroduced in runtime code, migrations, or frontend contracts:

- `zone / professional / subproject / custom` as engineering object types.
- `zone_object_id / professional_object_id` task fields.
- `project_materials.professional_object_id` and `engineering_categories.professional_object_id`.
- `legacy_object_type`, deprecated object-type arrays, legacy bridge/backfill helpers, and old scope adapter functions.
- `/api/scope-dimensions`, `scope_dimensions`, and `project_scope_dimensions` as active application surfaces.

Professional/system/domain/method semantics remain business facts through `specialty_type`, `engineering_category_id`, `standard_work_code`, template metadata, and project profile facts. They are not range-tree objects.

Any older section in this document that mentions deleted object types, deleted fields, old scope tables, or compatibility adapters is superseded by this boundary.
# v1.4.20.1 工作台前端落地方案

本文件是 `v1.4.20权限角色与协作体系执行方案.md` §4 的前端实施细则，覆盖 `/workspace` 路由的视觉、交互、数据接入与分阶段落地策略。

设计基准：`design-system/workbuddy/MASTER.md` v1.3 规范，对齐 Dashboard 与 Milestones 当前视觉基线，遵守 v1.3.5.2 polish token。

## 1. 设计原则

```text
工作台是常驻整页路由，不做弹窗或 Sheet
弹窗只用于单次决策与轻量表单（公司切换、接受邀请、申请加入）
默认首页统一进入 /workspace，company_admin 在工作台内看到公司驾驶舱入口，regular 隐藏该入口
工作台是所有用户的冷启动入口；公司驾驶舱是管理视角，不承担首次使用入口
工作台所有 Section 都有 loading、empty、error 三态，不依赖弹窗承担主交互
```

### 3.2 默认导向逻辑

```text
登录后落点由 RootRedirect 组件计算：
  permissionSystemDisabled        -> /company（兼容旧禁用权限模式）
  权限系统启用后，所有已登录用户默认 -> /workspace
  company_admin 不直接进入 /company，而是在 /workspace 通过顶部 tab 或管理入口进入公司驾驶舱
未登录用户访问 /workspace 或 /          -> 触发 openLoginDialog，本路径不变（保留 deep link）
```

### 3.3 退出登录回跳

当前 `client/src/components/layout/Header.tsx` 退出登录硬编码 `navigate('/company?login=1...')`，对 regular 用户会再次落到他无法操作的公司驾驶舱。v1.4.20.1 必须改写：

```text
退出后默认目标：统一回到 /workspace 登录态入口，未登录态保留 redirect 参数
  所有已登录身份退出后 -> /workspace?login=1&redirect=...
未知 / 未加载完成的角色：退化为 /workspace?login=1&redirect=...
不允许：硬编码 /company；登录页关闭后直接覆盖 deep link
```

重新登录后的 redirect 必须考虑跨公司情况，避免用户撞向 v1.4.20 §4.9 业务化阻断页：

```text
登录成功后解析 redirect 目标 URL：
  若目标命中 /projects/:id/* 且项目属于用户某个已加入公司：
    自动切换 currentCompanyId 到该项目所属公司
    toast 提示"已切换到 {公司名}"
    再 Navigate 到 redirect 目标
  若目标项目不属于用户任何已加入公司：
    Navigate 回 /workspace
    toast 业务化提示"原页面所属公司不可访问"
  若目标为公司级路由 /company：
    检查用户当前公司是否为 company_admin，无则 fallback 到 /workspace
该逻辑在 RootRedirect 与 LoginDialog 关闭回调内统一封装为 resolveLoginRedirect 工具函数
不允许：登录后立即丢用户到业务化阻断页
```

### 3.4 Header 顶部 tab

```text
非项目页面（pathname 命中 /workspace、/company、/notifications）显示主导航 tab：
  全员可见：工作台 (/workspace)
  仅 company_admin 可见：公司驾驶舱 (/company)
  (本期不引入更多顶部 tab，提醒中心仍走铃铛入口)
项目页面（/projects/:id/*）不展示 tab，保持当前 Sidebar 体验
tab 视觉沿用 v1.3 SegmentedControl pill 样式，与 GanttViewHeader 视图切换一致
```

### 3.5 Sidebar 在不同路由下的处理

当前 `client/src/components/layout/Sidebar.tsx` 按 `isProjectPage` 切换 PROJECT_NAVIGATION 与 COMPANY_NAVIGATION，落到 /workspace 时会渲染 COMPANY_NAVIGATION 的"公司驾驶舱 + 提醒中心"两项，对 regular 用户会引导他撞业务化阻断页。v1.4.20.1 必须收口：

```text
/workspace 路由：
  完全隐藏 Sidebar
  主导航完全由 Header 顶部 tab 承担
  全屏宽度让 WorkspacePage 的 Section 横向展开，提升信息密度与商业级观感
/projects/:id/* 项目内：
  保留现有 Sidebar 行为（PROJECT_NAVIGATION 完整项目级导航）
/company 公司驾驶舱：
  保留现有 Sidebar 行为（COMPANY_NAVIGATION 简化导航）
/notifications：
  跟随上一条用户来源页保持一致：
    从 /workspace 进入 -> 隐藏 Sidebar
    从 /projects/:id/* 进入 -> 项目 Sidebar
    从 /company 进入 -> 公司 Sidebar
移动端：
  /workspace 下原 Sidebar 抽屉入口（左上角 Menu 按钮）改为指向 Header tab 切换
  避免移动端用户被困在工作台无法切换驾驶舱
不允许：
  /workspace 与 Sidebar 同时显示，造成主导航与 Header tab 重复
  /workspace 下 Sidebar 仅显示"公司驾驶舱"一项却又对 regular 不可点击
```

### 3.6 业务化阻断

## 4. /workspace 三种状态

### 4.1 状态判定

后端 `/api/workspace` 聚合接口返回的 payload 直接决定状态：

```text
{
  hasCompany: boolean,
  currentCompany: { id, name, role } | null,
  switchableCompanies: [],
  myProjects: [],
  recentProjects: [],
  companyProjects: [],
  pendingInvitations: [],
  joinableProjects: [],
  joinRequests: [],
  demoEntry: { title, route, enabled },
  emptyStateReason: 'no_company' | 'no_project_membership' | 'pending_approval' | null,
}
```

```text
NO_COMPANY     hasCompany = false
EMPTY_PROJECTS hasCompany = true && myProjects = []
NORMAL         hasCompany = true && myProjects.length > 0
```

## 7. 数据接入

工作台所有 Section 直接消费 v1.4.20 提供的接口，前端不做二次聚合或临时拼装：

```text
GET /api/workspace                      聚合接口，单次请求填满整页
POST /api/workspace/companies/switch    切换公司
POST /api/companies                     创建公司（创建公司引导 Sheet 提交目标）
POST /api/companies/join                使用 company_invitations 邀请码加入公司，或申请加入 searchable 公司
GET  /api/companies/search?q=           搜索 searchable 公司极简信息
POST /api/project-direct-invitations/:id/accept   接受工作台定向项目邀请
POST /api/project-direct-invitations/:id/decline  拒绝工作台定向项目邀请
POST /api/projects                      创建公司后的"创建第一个项目"引导（接 v1.4.20 §4.4 定义的工程类型 / 计划树草案流程）
POST /api/projects/:id/join-request     申请加入 company_visible 项目
GET  /api/demo-projects                 点击 /demo 后懒加载演示项目详情
```

公司切换必须调用 `POST /api/workspace/companies/switch`，并以服务端返回结果更新 `currentCompanyId` 与本地缓存；不得只改 localStorage。创建公司成功后，前端只进入“创建第一个项目”引导，不把创建公司和创建项目合并成一个事务。

封装统一 hook `useWorkspaceData`，对外暴露 currentCompany / myProjects / recentProjects / companyProjects / pendingInvitations / joinableProjects / joinRequests / demoEntry / emptyStateReason 等扁平字段；请求级 loading / error 由 hook 处理，UI 组件只关心字段值与回调。

`pendingInvitations` 只允许由后端 `project_direct_invitations` 生成。既有 `project_invitations` 是项目通用邀请码 / 链接，没有 invitee 和 declined 状态，前端不得把它拼装成“待处理邀请”。

接口契约测试要求：

```text
新增 WorkspaceApiContract.test.ts 或等效测试，固定 /api/workspace payload 字段、空数组默认值、角色枚举、错误码映射
前端不得自行补造 currentCompany、companyProjects、joinRequests、joinableProjects、demoEntry；缺字段视为后端契约失败
viewer 不得出现在 WorkspaceProject.myRole、PendingInvitation.role、RoleChip.role 等前端有效角色枚举中
company_admin 项目卡片只作为当前公司 owner 等效展示，不写入项目成员关系
```


## 14. 边界场景行为表

下表枚举工作台必须实现的边界场景与明确行为，未列出场景按 v1.4.20 §4.9 业务化阻断处理，不允许沉默失败。

```text

  顶部 banner role=alert：当前无法加载工作台，请检查网络或稍后重试。
  保留 Header tab 与 ContextStrip 占位骨架，主区显示 retry 按钮
  不允许：直接全屏白屏或 toast 后留空

场景 2  /api/workspace 403（账号被禁用 / 公司被删除）
  渲染业务化阻断页：当前账号无可访问公司，请联系管理员
  Header 仅保留头像菜单与退出登录入口

场景 3  NORMAL 状态点击 QuickMetricRow 待处理邀请卡片，但 PendingPanel 为空（数据竞态）
  滚动到顶部，触发一次 refresh()；若仍为空，toast 业务化提示"暂无待处理邀请"
  不允许：scrollIntoView 到不存在的锚点造成视觉跳变

场景 4  MyProjects company_admin 切换"公司全量"tab 时，公司全量项目数 > 200
  仍渲染网格，但分页 page=1 size=50；底部"加载更多"按钮 + 计数 50 / 200
  网格视图保留筛选状态；切换到列表视图时复用筛选

场景 5  公司切换中，当前页是 /projects/:id/*
  整页骨架替换；切换完成后调用 v1.4.20 §4.9 的可见性校验

场景 6  接受邀请成功后立即被原邀请人撤销
  toast 业务化提示：邀请已被撤销，请联系邀请人确认
  PendingPanel 该条目移除；不允许：进入项目后 403 才报错

场景 7  申请加入项目时项目可见性被改为 private
  RequestJoinSheet 提交时后端返回 409
  Sheet 内显示行内错误：该项目已不可申请；保留用户填写的理由便于复制；提供"返回工作台"按钮

场景 8  RecentProjects 项目在 myProjects 之外（用户被踢出但 recent 未刷新）
  点击卡片时拦截，业务化提示并触发 refresh()
  不允许：直接 Navigate 后撞业务化阻断页

场景 9  公司切换 dropdown 中当前公司被高亮但点击
  关闭 dropdown，不重复触发切换；不显示 toast
  键盘 Esc 关闭 dropdown，焦点回到触发按钮

场景 10 单项目用户的 MyProjects 视图切换
  虽布局简化为单卡放大，仍保留视图切换 SegmentedControl，方便后续项目数量变化
  网格 / 列表切换状态写入 localStorage，跨会话保留

场景 11 NO_COMPANY 用户在头像菜单点击"产品功能引导"
  允许重新触发工作台层 3 步引导；项目层 6 步因无项目入口跳过
  toast 提示"暂无项目层引导可重看"

场景 12 跨公司项目 URL 直接访问，但用户已在该项目所属公司
  resolveLoginRedirect 检测匹配，无需切换；直接 Navigate
  不弹 toast，不弹 ConfirmDialog

场景 13 用户在 Sheet 打开期间收到实时事件（邀请变更 / 申请审批）
  Sheet 自身状态不刷新，避免破坏用户输入
  Sheet 关闭后调用 refresh() 拉最新数据
  实时事件影响的 Section 在 Sheet 之外正常乐观更新

场景 14 prefers-reduced-motion 用户访问
  Section 错峰进场降为同步显示
  hover translate-y 取消，仅保留 shadow 与边框变化

场景 15 用户在 /workspace 触发 LoginDialog 重新登录（token 过期）
  保留 /workspace 路径
  登录成功后调用 resolveLoginRedirect，命中 /workspace 自身则直接刷新数据
  不允许：登录后强制跳 /company 或 /
```

## 15. 性能指标

工作台是高频入口，必须按商业级 SaaS 性能要求落地：

```text
首屏 LCP（Largest Contentful Paint）目标：
  桌面端 ≤ 1.5s（中位数）
  移动端 ≤ 2.5s
  主要 LCP 元素：MyProjects 第一行第一张项目卡
首屏 TTI（Time to Interactive）目标：
  桌面端 ≤ 2.5s
  移动端 ≤ 4s
骨架持续时间：
  最短 200ms（避免快闪 flash）
  超过 300ms 仍未返回数据，触发分段骨架升级到加载提示文案
  超过 8s 仍未返回，提示用户检查网络并暴露 retry
请求并行度：
  /api/workspace 必须是单次请求聚合，不允许前端拆 5+ 个并发请求拼装
  邀请 / 申请审批动作 / 演示项目详情 lazy fetch 不阻塞首屏
prefetch 与缓存：
  最近 3 个项目的 dashboard summary 在工作台加载完成后 idle prefetch
  hover RecentProjects 卡片时 prefetch 对应项目 dashboard
  当前项目未引入 React Query / SWR 时，不新增缓存框架；使用现有 requestJson + useWorkspaceData 内存状态 / Zustand 或既有本地缓存封装实现 stale-while-revalidate 5 分钟
  若实施期决定新增 React Query / SWR，必须先登记依赖、包体积影响和迁移范围，不得默认假设项目已有该缓存层
bundle 体积：
  WorkspacePage 与其子组件 lazy 加载，初始 chunk 增量 ≤ 30 KB gzip
  PreviewEntry 只渲染 /api/workspace 返回的 demoEntry 入口元信息；演示项目详情仅在点击 /demo 后加载
不允许：
  阻塞首屏的同步用户头像加载
  非必要的额外 Sentry / analytics 请求阻塞首屏
  Workspace 子组件直接 import 项目级页面（造成 bundle 串联）
```

## 多公司空间与数据隔离统一口径

本文件执行时必须承接 `v1.4.20 权限角色与协作体系执行方案` 的多公司空间要求。除非本文件明确声明为 `system_seed`、全局字典或演示样例数据，否则所有项目级数据都必须先归属于项目，再通过项目解析到所属公司。

```text
所有新增表：优先包含 project_id；确属公司级数据时包含 company_id；确属系统公共数据时标记 scope = system_seed / global_dictionary。
所有查询：先按 currentCompanyId / company_id 隔离，再按项目权限过滤，不允许前端二次过滤替代后端隔离。
所有写入：前端通过 apiClient 注入 X-Company-Id；不得把 query/body currentCompanyId 当成权限依据。
所有汇总：公司级汇总只统计当前公司项目；项目级汇总只统计当前项目；演示项目不进入真实公司汇总和真实项目统计。
所有引用：禁止跨公司引用任务、工程对象、范围维度、责任单位、图纸、证照、验收、风险、问题、预警、计划、模板沉淀和经验数据。
所有模板 / 经验数据：系统公共种子可跨公司复用；公司沉淀模板、公司经验工期、公司历史数据只能在当前公司内使用。
所有旧数据：没有 company_id 的历史数据在迁移时归入默认公司，并保留兼容读取；不得因为补公司空间而删除旧对象。
```

本文件如出现“全部项目”“公司汇总”“项目列表”“可见项目”等表述，执行层一律理解为：先限定当前公司，再按 v1.4.20 的 `owner / editor / 当前公司 company_admin / regular` 权限模型过滤。
