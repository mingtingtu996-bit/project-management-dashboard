## T3. Supabase 返回类型 — `progress` 字段跨服务反复 `Number()` 强转

TypeScript 类型定义 `Task.progress: number`，但 Supabase SDK 实际返回的可能是 `string | null`。全仓有 **15+ 处** `Number(task.progress ?? 0)` 手动强转。

**涉及文件**：
- `projectExecutionSummaryService.ts`（3 处）
- `dataQualityService.ts`（7 处）
- `routes/tasks.ts`（3 处）
- `routes/acceptance-plans.ts`（1 处）
- `routes/task-summaries.ts`（4 处）

**建议**：在 `dbService.ts` 的查询层统一做类型归一化——从 Supabase 读出后立即 `Number()` 转换，下游不再需要逐处强转。或在 Supabase 表定义中确认 `progress` 列类型为 `integer`/`numeric`。

## T7. 前端内部双轨：`dashboardStatus.ts` 与 `taskBusinessStatus.ts`

两个前端文件在同一代码库中定义了同名函数：

| 函数 | `dashboardStatus.ts` | `taskBusinessStatus.ts` |
|------|---------------------|------------------------|
| `isCompletedTask` | `已完成, completed`（缺 `done`，`progress === 100` 严格等于） | `completed`（缺 `done, 已完成`，`progress >= 100`） |
| `isActiveRisk` | 排除 `resolved/已解决/mitigated/closed` | 使用 `CLOSED_RISK_STATUSES` Set |
| `isActiveObstacle` | 有 | 有 |
| `isPendingCondition` | 有 | 有 |

**性质**：同一前端代码库两份判定函数，不同页面引用不同版本，UI 计数可能不一致。

**建议**：合并为一份，统一放到 `taskBusinessStatus.ts`，`dashboardStatus.ts` 删除或改为纯 re-export。
