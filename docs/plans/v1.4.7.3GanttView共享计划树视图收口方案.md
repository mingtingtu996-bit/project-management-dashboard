## 0. 2026-06-01 final range-tree boundary (authoritative)

This v1.4-series plan follows the final range-tree model. There is no production history or existing user data that needs a compatibility layer.

Authoritative engineering object types are exactly: `phase / section / building / basement / floor / physical_zone / functional_area`.

The following compatibility surfaces are deleted and must not be reintroduced in runtime code, migrations, or frontend contracts:

- `zone / professional / subproject / custom` as engineering object types.
- `zone_object_id / professional_object_id` task fields.
- `project_materials.professional_object_id` and `engineering_categories.professional_object_id`.
- `legacy_object_type`, deprecated object-type arrays, legacy bridge/backfill helpers, and old scope adapter functions.
- `/api/scope-dimensions`, `scope_dimensions`, and `project_scope_dimensions` as active application surfaces.

Professional/system/domain/method semantics remain business facts through `specialty_type`, `engineering_category_id`, `standard_work_code`, template metadata, and project profile facts. They are not range-tree objects.

Any older section in this document that mentions deleted object types, deleted fields, old scope tables, or compatibility adapters is superseded by this boundary.
# v1.4.7.3 GanttView 共享计划树视图收口方案

## 1. 背景

`v1.4.7.1 共享计划树底座优化升级执行方案` §7 要求项目基线、月度计划、任务列表三页共用同一渲染形态、同一工具栏、同一视图切换、同一编辑/阅读态切换规则。

当前实现现状：

```text
BaselinePage / MonthlyPlanPage：通过 PlanTreeEditor 包裹 PlanningTreeView，符合 v1.4.7.1 §7 约束
GanttView 历史实现：使用 GanttTaskRows + PlanningTreeTable，PlanningTreeView 工具栏被禁用，自己渲染 GanttViewHeader
GanttView 当前实现：GanttTaskPlanningTreeAdapter 承接 PlanningTreeTable 拼装，PlanningTreeView 工具栏 / 视图切换 / 业务动作 slot 已恢复为共享表面
```

差异点：

```text
视图切换按钮组语义不同（列表/卡片/详情 vs 列表/横道图）
工具栏来源不同（PlanningTreeView 自带 vs GanttViewHeader 独立）
编辑态顶部状态条 GanttView 缺失
行高 token GanttView 永远固定 36px（列表）
外层壳 GanttView 不走 PlanningPageShell + PlanningWorkspaceLayers
```

v1.4.7.3 的目标是把 GanttView 改为薄壳，让"列表/卡片/详情/横道图"四种视图全部承载在 PlanningTreeView 内部，达成 v1.4.7.1 §7 所约束的"三页真正长得一样"。

## 2. 执行边界

```text
本方案不替代 v1.4.7.1，不替代 v1.4.7.2，只为 GanttView 与共享计划树底座对齐补丁
不改变 v1.4.7 三层语义（基线 = 承诺快照、月计划 = 周期计划、任务列表 = 实时执行事实）
不替换甘特图渲染引擎，横道图渲染路径保留现有 GanttView 内部实现，仅在 PlanningTreeView 内分支调用
不改造列表 / 卡片 / 详情视图，已由 v1.4.7.1 §7 落地
不引入 CRDT / OT 协作，保留 v1.4.7.1 mergeGroup 协作模型
不引入新 surface 类型；surface 仍为 baseline / monthly_plan / task_list
```


### 3.2 PlanningTreeView slot 接口冻结

PlanningTreeView 通过 slot prop 让外层页面注入页面级差异化内容。slot 接口在 v1.4.7.3 内冻结，后续扩展必须先更新本方案。

```typescript
export type PlanningSurface = 'baseline' | 'monthly_plan' | 'task_list'
export type PlanningView = 'list' | 'card' | 'detail' | 'gantt'

export interface PlanningTreeViewProps {
  surface: PlanningSurface
  enabledViews: PlanningView[]
  defaultView?: PlanningView
  columns: PlanningTreeColumn[]

  // 数据与编辑回调（已存在字段保持不变）
  rows: PlanningRow[]
  fieldRegistry: FieldRegistryVersionPayload | null
  onCommit: (operations: PlanningTableOperation[]) => Promise<CommitResult>
  onReadRefresh?: () => Promise<void>
  onEnterEdit?: () => void
  onExitEdit?: (saved: boolean) => void

  // 业务动作 slot：阅读态与编辑态分别注入
  readBusinessActionsSlot?: ReactNode
  editBusinessActionsSlot?: ReactNode

  // 横道图渲染分支
  ganttRenderer?: (props: GanttRendererProps) => ReactNode

  // 其余通用 slot
  emptyStateSlot?: ReactNode
  errorBannerSlot?: ReactNode
}

export interface GanttRendererProps {
  rows: PlanningRow[]
  selectedRowIds: string[]
  onRowClick: (rowId: string) => void
  onScaleChange?: (scale: 'day' | 'week' | 'month') => void
  scale: 'day' | 'week' | 'month'
  readOnly: boolean
}
```

约束：

```text
slot 名称使用 readBusinessActionsSlot / editBusinessActionsSlot 区分阅读态与编辑态业务动作
slot 不暴露给 BaselinePage / MonthlyPlanPage 滥用：基线发布、月计划确认必须仍通过该 slot 注入，不允许通过 PlanningTreeView 内部分支特判 surface
ganttRenderer 仅在 surface === 'task_list' 且 enabledViews 包含 'gantt' 时生效
不允许：drawerSlot 等其他 slot；甘特独有抽屉 / 对话框由 GanttView 在外层渲染，与 PlanningTreeView 解耦
```
