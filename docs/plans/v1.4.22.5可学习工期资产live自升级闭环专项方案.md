# v1.4.22.5 可学习工期资产 live 自升级闭环专项方案

> 本文件承接 v1.4.22.4 的收口结论。
> v1.4.22.4 证明“工期精度闭环边界、核心 runtime 校准、事实锁定、验收矩阵已收口”。
> v1.4.22.5 专门证明“所有可学习的工期预测与计划网络资产，是否真的进入 live 自学习 / 自升级闭环”。

## 0. 结论口径

允许达成的目标口径：

> 所有可学习的工期预测与计划网络资产，都已进入 live 自学习 / 自升级闭环；事实与承诺层保持锁定，只作为样本、验收和回放依据。

禁止达成或宣传的口径：

> 所有工期相关资产都已经 live 自学习、自我升级。

禁止原因：actual start/end、completion status、baseline、monthly plan、progress snapshot、用户确认依赖、用户确认关键路径等是事实或承诺，不是学习系统的 runtime writer。

## 1. 与 v1.4.22.3 / v1.4.22.4 的关系

| 文件 | 职责 | 不能替代 |
| --- | --- | --- |
| v1.4.22.3 | 治理控制面：资产登记、release-exit、rollback、冲突清理、发布锚点 | 不能证明数字更准 |
| v1.4.22.4 | 精度执行面：prediction event、actual outcome、MAE / Bias / overcompensation、runtime consumption、事实锁定验收 | 不能证明所有可学习资产都已 live 消费 |
| v1.4.22.5 | live 自升级闭环：逐项判定可学习资产是否具备五项闭环条件 | 不能把事实层改造成学习 writer |

代码边界：

- `durationPrecisionGovernanceBoundaryService.ts`：区分 v1.4.22.3 governance control、v1.4.22.4 precision learning、business fact lock。
- `durationLiveLearningClosureService.ts`：区分可学习资产、计划网络资产、事实锁定资产，并判定 live 自学习声明是否成立。

## 2. 五项强制闭环条件

每个可学习工期资产要被声明为 live 自学习，必须同时满足以下五项条件：

| 条件 | 代码字段 | 验收证据 |
| --- | --- | --- |
| 资产分级强约束 | `assetClass / canLearn / factLocked / selfLearningPublishAllowed / runtimeWriterRequired / publishGateRequired` | `durationLiveLearningClosureService.ts` 登记，测试覆盖标准工序 seed、专项工序 seed、依赖、关键路径、事实层 |
| prediction / outcome 事件 | `predictionEventRecorded / actualOutcomeEventRecorded` | 每次预测有输入、资产版本、输出影响；完工后有 actual outcome 与样本健康 |
| global / industry / company / project 分层学习 | `tieredLearningPolicyRegistered / enabledLearningScopes` | 冷启动可回退到全局/行业，公司和项目样本成熟后逐层覆盖 |
| runtime consumer 消费 published / canary artifact | `runtimeConsumerUsesPublishedArtifact` | 业务预测、剩余工期、赶工、依赖/WBS/关键路径消费者不再只看 report-only |
| 发布门禁与回滚闭环 | `releaseExitApproved / impactMonitoringReady / rollbackTargetReady / accuracyMetricsAvailable` | v1.4.22.3 release-exit 通过，v1.4.22.4 精度指标证明 MAE/Bias/过度补偿受控 |

任一条件缺失，只能说 `not_ready`、`candidate`、`evidence-only` 或 `shadow/report-only`，不得说 live 自学习。

## 3. 资产分级

| 资产族 | 资产键 | 分类 | 是否可学习 | runtime 声明边界 |
| --- | --- | --- | --- | --- |
| base 工期与冷启动 | `base_duration_benchmark`、`duration_cold_start_baseline` | `learnable_duration_prediction` | 是 | 可以在五项齐备后参与 runtime 预测，不写回事实 |
| 残差与置信度 | `forecast_residual_overlay`、`forecast_confidence_weight` | `learnable_duration_prediction` | 是 | published / canary 才能影响 runtime，shadow 只能留证据 |
| 标准工序 seed | `standard_work_duration_seed` | `learnable_duration_prediction` | 是 | replay 只能产候选，seed rewrite 需要专门 writer |
| 专项工序 seed / WBS / 依赖 / 关键路径 | `special_work_duration_seed`、`wbs_reference_days`、`dependency_rule_candidate`、`critical_path_rule_candidate` | `learnable_plan_network` | 是 | 先产网络 prediction/outcome，再通过 release-exit 与专项 writer |
| baseline / monthly / actual / progress | `baseline_commitment`、`monthly_plan_commitment`、`actual_duration_outcome`、`progress_snapshot` | `business_fact_lock` | 否 | 只做样本、验收、回放依据，不允许自学习改写 |

## 4. 分层学习规则

live 自升级不是单一公司桶学习，必须按以下顺序收敛：

1. `global`：全局默认基线，托底冷启动。
2. `industry`：行业/业态/项目类型基线，解决小账号长尾冻结。
3. `company`：公司级经验，样本达到门槛后覆盖上层。
4. `project`：项目内高频工序或局部节奏 overlay，样本足够时短周期校准。

下层样本不足时必须 shrink 到上层，不得用少量项目样本直接覆盖公司或全局经验。

## 5. 验收矩阵

| 验收项 | 通过条件 | 失败时口径 |
| --- | --- | --- |
| 单资产 live 自学习 | `evaluateDurationLiveLearningAsset(...).status = live_self_learning_ready` | `not_ready` |
| 全组合口径 | 所有可学习资产 ready，所有事实资产 `fact_locked_closed` | `not_ready_for_live_self_learning_claim` |
| 事实层保护 | 所有事实资产 `selfLearningPublishAllowed=false` | 阻断并返回 `duration_fact_auto_rewrite_blocked` |
| 禁止宣传语 | `prohibitedClaim = all_duration_assets_are_live_self_learning` 永远存在 | 不允许删除 |
| 正确宣传语 | `allowedClaim = all_learnable_duration_prediction_and_network_assets_are_live_self_learning;facts_and_commitments_remain_locked` | 未满足前不得使用 |

## 6. 实施顺序

1. 用 `durationLiveLearningClosureService.ts` 作为统一判定口，先拒绝错误宣传和事实层改写。
2. 给各可学习资产补 prediction event / actual outcome event。
3. 给冷启动、标准工序、专项工序、依赖/WBS/关键路径补 global / industry / company / project 分层策略。
4. 让 runtime consumer 逐个消费 published / canary artifact，并记录 consumer evidence。
5. 将 v1.4.22.3 release-exit、impact monitoring、rollback target 和 v1.4.22.4 accuracy metrics 绑定为统一发布门禁。
6. 每个资产族通过后，逐项从 `candidate/evidence-only` 升级为 `live_self_learning_ready`。

## 7. 当前状态

本文件创建时，代码已具备口径判定与阻断能力：

- `durationLiveLearningClosureService.ts` 已登记可学习资产和事实锁定资产；
- `durationLiveLearningClosureService.test.ts` 已覆盖资产分级、五项闭环、事实锁定、组合口径和缺口阻断；
- 这不等于所有业务 consumer 已经 live 消费所有资产，只说明系统已有统一判定口，后续实现必须以该判定口为准。

因此，当前可声明：

> live 自升级口径的代码级判定口已建立。

当前不可声明：

> 所有可学习工期资产已经全部 live 自学习。
