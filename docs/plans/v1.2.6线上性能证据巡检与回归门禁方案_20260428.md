# v1.2.6 线上性能证据巡检与回归门禁方案

编制日期：2026-04-28

## 1. 背景

v1.2.4 已建立线上性能证据上报，v1.2.5 已将证据聚合为 summary 与 release gate。下一步不应继续人工打开接口判断，而要把线上性能证据变成可执行巡检命令。

v1.2.6 不新增业务功能，只将线上性能证据纳入部署后巡检与回归门禁。

## 2. 收口目标

- 部署后自动验证 `/api/performance-reports/summary` 在线。
- 提供本地/运维可执行命令，读取线上 summary 并输出 `PASS` 或 `FAIL`。
- 默认允许 `insufficient_data`，因为当前尚未大规模使用，不因没有证据误阻断上线。
- 支持严格模式：可将 `watch` 或 `insufficient_data` 配置为失败，用于后续真实用户量起来后的门禁。

## 3. 本轮实施范围

### 3.1 巡检脚本

新增：

```bash
node scripts/check-performance-evidence-summary.mjs --url http://YOUR_SERVER
```

也可使用完整 summary 地址：

```bash
node scripts/check-performance-evidence-summary.mjs --url http://YOUR_SERVER/api/performance-reports/summary
```

脚本输出：

- release gate 状态。
- 当前窗口证据数量。
- 超阈值数量。
- TOP 慢 API。
- TOP 慢路由。
- release gate 原因。
- 下一步治理建议。
- 最终 `Result: PASS` 或 `Result: FAIL`。

### 3.2 package 命令

新增：

```bash
npm run verify:performance-evidence -- --url http://YOUR_SERVER
npm run verify:performance-evidence:unit
```

### 3.3 部署后探测

自有服务器部署脚本在 `/api/health` 成功后，额外请求：

```text
/api/performance-reports/summary
```

该步骤只验证接口在线。是否阻断由巡检脚本的 gate 策略决定。

## 4. 门禁策略

默认策略：

- `pass`：通过。
- `watch`：通过但输出 warning。
- `insufficient_data`：通过但输出 warning。
- `fail`：失败。

严格策略：

```bash
npm run verify:performance-evidence -- --url http://YOUR_SERVER --fail-on-watch --disallow-insufficient --max-threshold-exceeded 0
```

严格策略适合后续真实用户量起来后启用。

## 5. 本轮不纳入

- 不把 summary 接口强制接入 GitHub Actions 阻断部署。
- 不新增数据库性能历史表。
- 不新增前端性能看板。
- 不对具体页面做专项优化。

这些应基于 v1.2.6 巡检输出进入后续版本。

## 6. 验收命令

```bash
npm run verify:performance-evidence:unit
npx vitest run --root client src/pages/__tests__/Wave8PerformanceContracts.test.ts
npx vitest run --root server src/__tests__/performanceReportsRoute.test.ts
npm run typecheck --workspace=client
npm run typecheck --workspace=server
npm run lint --workspace=client
npm run build:client
npm run verify:client-bundle-budget
npm run build --workspace=server
```

上线后可执行：

```bash
npm run verify:performance-evidence -- --url http://YOUR_SERVER
```

## 7. 放行标准

- 本地测试、类型检查、构建、bundle budget 通过。
- 自有服务器部署成功。
- `/api/health` 返回 `{"status":"ok"}`。
- `/api/performance-reports/summary` 部署后可访问。
- 巡检脚本可对 summary 给出明确 `PASS` 或 `FAIL`。
